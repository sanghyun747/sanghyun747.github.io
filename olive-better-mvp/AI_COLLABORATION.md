# AI 협업 기록

## 협업 원칙

- 한 번에 한 단계만 변경하고 코드, 검증 증거, Git 커밋을 함께 남겼습니다.
- 화려함보다 요청→근거→판단→수정→발행→반응 재적용의 완결성을 우선했습니다.
- 사용자가 제공한 키는 사용·저장·출력하지 않았고 실제 공급자 호출도 수행하지 않았습니다.
- 원본 상품 데이터가 없는 점을 숨기지 않고 결정적 데모 데이터와 출처 문서를 만들었습니다.
- Probe/Cofa 화면에는 접근하지 않았으며 제출 가능한 로컬 산출물만 만들었습니다.

## Codex가 수행한 작업

| 단계 | 작업 | 검증 |
|---|---|---|
| 계약 | 목표·권한·예산·완료 게이트 고정 | agent-loop 계약 해시 고정 |
| 소스 | 서버, 도메인 로직, 운영자·고객 UI, 300개 데모 카탈로그 구성 | 실행·상품 수 확인 |
| RED | LLM 잘못된 성공, 고객 내부 데이터 누출, 반응 영역 위조 재현 | 3개 기대 실패 |
| FIX | 위 3개 결함과 기능 매칭을 최소 수정 | 집중 테스트 3/3 |
| 회귀 | 코어·API·보안·UI 계약 테스트 | 21/21 |
| E2E | 실제 HTTP와 브라우저에서 전체 사용자 흐름 수행 | API·브라우저 PASS |
| 화면 | 운영자·고객·모바일 화면 확인 | 콘솔 오류 0, 수평 넘침 0 |

## 사용 도구

- Codex 로컬 코드 편집·명령 실행
- `node:test`
- `agent-browser` 기반 실브라우저 자동화
- Git·GitHub 단계별 기록
- 설치된 `agent-loop`의 증거 게이트·복구·감사 절차

## 사람이 최종 확인할 것

1. 압축을 풀고 `npm test`, `npm start`를 실행합니다.
2. README의 3분 데모를 한 번 수행합니다.
3. 제출 전 압축 해시와 저장소 커밋을 확인합니다.
4. 외부 제출 버튼은 사람이 직접 누릅니다.
